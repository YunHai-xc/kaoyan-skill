# 入门引导：把模糊的话变成能筛的条件

用户开口时往往是这样的：

> 「我本科学的电子，想考计算机，家在河南，想去江浙沪，双非也能接受，但不想读那种学费特别贵的。」

这句话里有 6 条约束，但一条都不能直接查。这一节的工作是**把它拆成结构化字段**，然后再动手。

## 一、问的顺序：本科专业 → 跨不跨 → 别的都不问

**v0.3.2 修正过顺序。** 旧版先问"想考什么方向"，结果用户说不清，越问越发散（实测：法学 → 文科 → 中文，漂了三轮）。正确的是：**不跨考时，方向由本科专业直接决定，不用问。**

| 步 | 问什么 | 为什么 |
|---|---|---|
| **第 0 问（只此一问）** | 你本科读的什么专业？ | 决定候选方向集合；也决定有没有报考资格限制 |
| **第 1 问** | 跨不跨考？（不跨 / 跨相近 / 随便跨） | 不跨 → 直接查对口表给 2-4 个方向；跨 → 才需要问"想考什么" |
| **第 2 问** | 想去哪（城市/省份） | 砍池子 |
| **第 3 问** | 学硕还是专硕？考不考数学？ | **只在方向里真的存在分歧时才问**（中文只有学硕，就不问学硕专硕） |
| **第 4 问** | 层次、预算、能否二战 | 排序用，放最后 |

### 不跨考时：不要问"想考什么"，直接给清单

```
python scripts/recommend.py --undergrad-major 汉语言文学 --directions
```

```
| # | 代码 | 方向 | 学位 | 报考限制 | 备注 |
| 1 | 050100 | 中国语言文学（学硕） | 学术学位 | — | 两门业务课基本自命题 |
| 2 | 045300 | 国际中文教育 | 专业学位 | — | 原「汉语国际教育」 |
```

用户从这 2-4 行里挑一个即可。**这正是"不跨考方向小很多"的具体表现**——不是话术，是可枚举的清单。

### 跨考时才展开

跨考要额外查三件事，一件都不能省：

1. **该专业限不限跨考**（招生简章「报考条件」，如临床医学、法律（非法学）反向限制）
2. **要不要加试**（部分院校对跨考生复试加试两门本科主干课）
3. **专业课能不能补上**（跨考的最大成本，不是资格，是 0 基础）

## 二、模糊表述 → 结构化字段

这是整套引导的核心。用户的每句口语都要落到可执行字段上：

| 用户说 | 转成 | 依据 |
|---|---|---|
| 「想去江浙沪」 | `provinces: [上海, 江苏, 浙江]` | 省级池子 |
| 「不想离河南太远」 | `provinces: [河南, 湖北, 陕西, 山西, 河北]` | 邻省近似，并**明确告诉用户这是我的近似** |
| 「双非也能接受」 | `level: 不限` | 不筛层次 |
| 「想上个好点的」 | `level: 双一流`，并说明这只是一个标签，**不等于好考** | 研招网院校库标签 |
| 「家里经济一般」 | `max_tuition: 15000`，`dorm_required: true` | 见 `life.md`：专硕常常不给宿舍 |
| 「想上岸为主」 | `risk: 保守` → 优先 R4 一志愿录取率 >40%、统考名额 >50 | `school.md` 阈值 |
| 「想冲一把」 | `risk: 激进` → 可以看 R2/R5，但要写清代价 | 同上 |
| 「跨考」 | 标注 `cross_major: true` → 必须查该专业是否限制跨考、是否加试 | 简章报考条件 |
| 「本科是 XX 大学」 | `undergrad: XX大学` → 默认从候选里剔除（想换环境），可手动保留 | 见下 |

**用户说「不知道」时**，给默认值并标注：

- 专业方向不知道 → 按本科专业对应的专业学位类别起步
- 数学不知道 → 按「考数学、数二」准备（工科专硕最常见），**并说明这会限制可报范围**
- 城市不知道 → 先不筛，按「统考名额多、推免占比低」筛一轮，让用户看结果再定

## 三、产出：`assets/filters.json`

```json
{
  "updated": "2026-11-01",
  "undergrad": {"school": "XX大学", "major": "电子信息工程", "level": "普通本科"},
  "target": {"major_code": "085404", "major_name": "计算机技术", "degree": "专硕", "mode": "全日制"},
  "provinces": ["上海", "江苏", "浙江"],
  "level": "不限",
  "math": "数二",
  "cross_major": true,
  "max_tuition": 15000,
  "dorm_required": true,
  "risk": "保守",
  "notes": "用户原话：『双非也能接受，但不想读那种学费特别贵的』"
}
```

保留 `notes` 里的原话——半年后回看，这是唯一能还原「当时到底想要什么」的东西。

## 四、筛选的规矩（比功能本身重要）

1. **不做质量排名。** 没有全国统一的、可复核的院校质量数据，任何"第 1 名到第 10 名"都是编的。筛出来的短名单只按**约束是否满足**分组，不排名。
2. **池子只解决「有哪些学校」。** 某校有没有你的专业、招几个人，必须用 `check.py` 去查它的招生目录——池子不含专业信息。
3. **筛完立刻给下一步。** 每所候选后面写清「还缺什么、去哪查」，否则用户拿到名单也不知道该干什么。
4. **先说砍掉了什么。** 从 38 所筛到 9 所，要写清「因为什么筛掉 29 所」，用户才敢信这份名单。

## 五、跑法

```powershell
# 1) 建池子（已缓存则跳过，按需增量）
python scripts/pool.py --province 浙江 江苏 上海

# 2) 按 filters.json 筛出短名单
python scripts/screen.py --province 上海 江苏 浙江 --major 085404 --top 12

# 3) 对短名单里的重点校逐一深查（需要各自的招生目录入口页）
python scripts/check.py --school 杭州电子科技大学 --major 085404 --seed "<招生目录页>"
```

第 3 步的 `--seed` 目前需要人工给一次（研招网院校库不提供官网链接，见 `pipeline.md`）；
给过一次就记进 `data/sources.csv`，以后只写学校名。
